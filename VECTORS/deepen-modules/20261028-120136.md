## Position

Candidate 3 (the bookmarked split of `src/host.ts`) is built. It is uncommitted, together with candidates 1–2, the earlier subagent-queue work and the rename.

- `src/port.ts`: the seam to Pi (`send`, `idle`, `ui`, `emit`, `every`) and the real adapter `piPort`. Tests use a recording fake with a manual clock.
- `src/notifier.ts`: `createNotifier(port, state, changed)` with `settled`, `read`, `boundary`, `settle` and `drop`.
  - `boundary` appends to `event.entries`. In Pi's `emitBoundary`, the entries a handler returns replace the entries of earlier handlers.
  - `changed` repaints the footer when a delivery or a read stamp changes.
  - An epoch stops a send that fails after `drop()` from coming back.
- `src/footer.ts`: `createFooter(port, counts, state)` with `publish`, `open` and `close`.
  - It writes only through `setStatus`. The user dropped the zentui custom variable because zentui's minimalist editor showed it twice.
  - The spinner is taken over in `open()`, not at module load. Only the instance that opened last may spin.
- `src/host.ts`: 43 lines. It holds only the globalThis record that outlives `/reload`, the migration from older builds, and the module instances.
- `src/jobs.ts` calls `notifier.settled` and `notifier.read`, and `footer.publish`. `src/index.ts` is still the only place that wires hooks.
- Decision (user): "append only" for boundary delivery. If Pi discards invalid boundary entries, the wake-up is lost, and the job stays visible as unread in bg_logs. There is no in-flight state and no session-branch check. Pi does not expose `entry_appended` to extensions. `ctx.sessionManager.getBranch()` would make that check possible.
